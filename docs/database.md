# Database Reference

RollCall uses Cloud Firestore. Realtime Database is not used by the application and is locked down by `firestore/database.rules.json`.

## Collections

### `users/{uid}`

The document ID is the Firebase Authentication UID.

| Field | Type | Meaning |
| --- | --- | --- |
| `uid` | string | Firebase Auth UID; duplicated from the document ID by the admin route |
| `email` | string | Account email |
| `displayName` | string | Name displayed in the app |
| `role` | `"admin" \| "lecturer" \| "student"` | Authorization role |
| `faceDescriptor` | number[] \| null | 128-value face embedding, or null before registration |
| `createdAt` | number | Epoch milliseconds |

Created by `POST /api/auth/session` for admin-provisioned lecturer/student accounts. Students update only their own `faceDescriptor`; admins can write user documents.

### `courses/{courseId}`

| Field | Type | Meaning |
| --- | --- | --- |
| `name` | string | Course title |
| `code` | string | Course code |
| `lecturerId` | string | UID of the assigned lecturer |
| `enrolledStudentIds` | string[] | Student UIDs enrolled in the course |
| `createdAt` | number | Epoch milliseconds |

The course ID is generated by Firestore. Enrollment is represented as an array, not a subcollection.

### `attendanceSessions/{sessionId}`

| Field | Type | Meaning |
| --- | --- | --- |
| `courseId` | string | Parent course ID |
| `courseName` | string? | Optional display snapshot |
| `courseCode` | string? | Optional display snapshot |
| `createdBy` | string | Lecturer/admin UID that created the session |
| `date` | string | ISO calendar date, for example `2026-08-23` |
| `startTime` | number | Epoch milliseconds when the session was created/opened |
| `endTime` | number \| null | Epoch milliseconds when closed, otherwise null |
| `status` | `"open" \| "closed"` | Whether recognition is allowed |

### `attendanceSessions/{sessionId}/records/{uid}`

The record document ID is the student UID. Writes are server-only.

| Field | Type | Meaning |
| --- | --- | --- |
| `uid` | string | Type-level representation of the document ID |
| `studentUid` | string | Duplicate of the document ID used for collection-group filtering and rules |
| `studentName` | string? | Optional denormalized display name |
| `markedAt` | number | Epoch milliseconds |
| `confidence` | number \| null | face-api distance; lower is a closer match; null for manual entry |
| `method` | `"recognized" \| "manual_override"` | How the record was created |
| `confirmedBy` | string \| null | Lecturer/admin UID for manual confirmation |

The record is written with merge semantics, so a student has at most one record per session. A later mark can update the same document.

## Queries and indexes

- Admin users query `users` by `role == "lecturer"` or `role == "student"`.
- Lecturers query `courses` by `lecturerId == currentUser.uid`.
- Lecturers query `attendanceSessions` by `createdBy == currentUser.uid`.
- Reports query sessions by `courseId` and then read each session's `records` subcollection.
- A student's history uses a collection-group query on `records` with `studentUid == currentUser.uid`.
- `firestore/firestore.indexes.json` explicitly provides ascending and descending collection-group indexes for `records.studentUid`.

## Rules summary

- A signed-in user can read courses and sessions.
- A user can read their own user document; lecturers/admins can read user documents for roster/admin screens.
- Only admins write courses.
- Lecturers/admins create sessions; only the creator can update a lecturer-owned session; admins can update/delete sessions.
- Clients cannot write attendance records directly. All record writes go through the Admin SDK.
- Realtime Database reads and writes are denied.

Deploy rules and indexes with the Firebase CLI after reviewing them:

```bash
firebase deploy --only firestore:rules,firestore:indexes,database
```
